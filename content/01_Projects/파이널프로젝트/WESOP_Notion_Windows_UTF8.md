## 3. 경쟁시장 분석

### 3.1 급구

급구의 핵심 경쟁력은 ==**실시간 초단기 인력 연결**==이다.

2026년 상반기 급구 매출은 전년 동기 대비 약 2배 성장했고, 운송·물류 분야 임금 거래액은 전년 동기 대비 약 **11배 증가**했다. 외식·음료에서도 근무 완료 일자리는 전년 동기 대비 62%, 임금 거래액은 1.8배 증가했다.  
출처: [전자신문](https://www.etnews.com/20260727000207)

#### 급구가 증명한 것

> 정규직 채용만 HR 시장이 아니다.  
> “==오늘 18:00~22:00 사람이 필요하다”라는 수요 자체가 하나의 HR 시장==이다.

#### 강점

- 실시간 인력 수요 대응
- 초단기 근무
- 긱워커 중심
- 물류·외식 등 변동성이 큰 산업에 적합
- 빠른 인력 매칭 UX

#### 위솝이 그대로 따라가면 안 되는 이유

급구의 핵심 전장에서 경쟁하면 결국 다음 네트워크 효과 싸움이 된다.

```text
구직자 수 × 사업장 수 × 공고 수 × 매칭 속도
```

위솝이 가져가야 하는 전장은 다르다.

### 3.2 당근알바* 단점 : ==사업장 중심의 근로자 관리==
(즉, 사업장이 원하는 일정로 정하는 경우가 많아서 그때그때만 일하고자 하는 근로자의 사정과 불일치하는 경쟁력 저하가 있음)
로 인해 근로제공자에게 실제로 좋은 업무경험이 제공되는 것이 적다(입금도 느림)

당근의 가장 큰 무기는 **Hyper-local Network**다.

2025년 당근알바에서 가장 많은 지원이 발생한 거리는 **1~2km**였으며 전체 지원 중 15.6%를 차지했다.  
출처: [당근 보도자료](https://about.daangn.com/company/pr/archive/%EB%8B%B9%EA%B7%BC%EC%95%8C%EB%B0%94-%EC%A7%80%EC%97%AD%EB%B3%84-%EC%9D%BC%EC%9E%90%EB%A6%AC-%EC%97%B0%EA%B2%B0-%EB%8D%B0%EC%9D%B4%ED%84%B0-%EA%B3%B5%EA%B0%9C/)

또한 2025년 한 해 당근알바 누적 지원 횟수는 **5천만 회 이상**으로 보도됐다.  
출처: [이코노믹데일리](https://m.economidaily.com/amp/20251218084729481)

```text
지역 사용자 → 동네 → 근거리 알바 → 빠른 지원
```

#### 강점

- 막대한 사용자 풀
- 초지역 기반 탐색
- 낮은 서비스 진입장벽
- 생활권 기반 일자리
- 강한 소비자 네트워크 효과

#### 위솝과의 차이

- 당근: **사람 → 근처 일자리 탐색**
- 위솝: **사업장 운영상황 → 필요한 인력 예측 → 적합한 사람 탐색**

### 3.3 알바몬

알바몬 역시 AI 기반 인재 추천·매칭과 근무관리 영역을 강화하고 있다.  
출처: [한국경제](https://www.hankyung.com/article/2025032433531)

따라서 단순한 “AI가 알바를 추천한다”는 기능도 차별화 요소가 아니다.

### 3.4 샤플 등 Workforce Management

샤플과 같은 서비스는 근태 및 인력관리를 중심으로 B2B Workforce Management 영역을 공략하고 있다.  
출처: [샤플](https://www.shoplworks.com/)

위솝의 장기 경쟁력은 다음 결합에서 만들어진다.

```text
Workforce Management + Workforce Marketplace + AI
```

## 5. 위솝의 Data Moat

샵솔의 가장 중요한 자산은 앱 자체가 아니라 **운영 과정에서 발생하는 데이터**다.

```text
사업장
├── 업종
├── 지역
├── 근무시간
├── 근무스케줄
├── 직원
├── 출퇴근
├── 지각
├── 결근
├── 실제 근무시간
├── 급여
├── 업무일지
├── 체크리스트
└── 반복 근무 패턴
```

### 예시

```text
금요일 17:00~22:00
강남 음식점
최근 12주 데이터 분석

→ 평균 필요인력 5명
→ 현재 예약 인력 4명
→ 결근 위험 12%
→ 1명 추가 확보 권장
```

시스템이 이를 먼저 감지하고 다음 조건에 맞는 근로자에게 제안한다.(실제로는 제안을 받아서 지원하기보다는 지원을 할 수 있는 시간적 상태가 도래했을때 지원을 하는 어려움이 있기에 선제적 요청을 보내는 방식으로는 근로제공자 중심의 소통이 되기가 어렵다)

```text
2km 이내
+ 17:00~22:00 근무 가능
+ 음식점 경험
+ 최근 근무 신뢰도 우수
+ 요구 시급 충족
```

#### Strength

- 급여 기능
- 직원관리
- 업무관리

- 사업장 네트워크
- 진행 중인 AI HR R&D

#### 가장 중요한 차별점

> **채용 결과 이후의 데이터를 가지고 있다.**

일반 채용 플랫폼은 채용 성공 이후 데이터가 단절된다.

```text
채용 → 데이터 단절
```

샵솔은 다음 단계까지 연결할 수 있다.

```text
채용 → 실제 근무 → 출근 → 퇴근 → 급여 → 업무 → 재고용
```

### 8.2 Customer

#### 사업주 Persona

Pain Point:

- 갑자기 직원이 빠짐
- 채용 공고 작성이 번거로움
- 지원자의 적합성을 판단하기 어려움
- No-show 발생
- 급하게 사람이 필요함
- 근태와 급여 관리가 분리돼 있음

#### 사업주 JTBD

> 사람을 채용하고 싶은 것이 아니라 **필요한 시간에 매장이 정상적으로 돌아가게 하고 싶다.**

#### Worker Persona

N잡 근로자의 JTBD는 다르다.

> 직장을 찾는 것이 아니라 **내 빈 시간으로 돈을 벌고 싶다.**

```text
화요일 18~22시
목요일 19~23시
토요일 오후
        ↓
가능한 Shift 자동 추천
```

### 8.3 Competitor

- 급구: 시간 기반 초단기 시장
- 당근: 거리 기반
- 알바몬: 공고·검색 기반
- 위솝 제안: **운영 데이터 + 시간 + 거리 + 신뢰도 기반**

## 12. 핵심 기술 원칙

### LLM이 매칭 점수를 직접 결정하게 하면 안 된다

핵심 Match Engine은 LLM이 아니라 다음 구조가 적합하다.

```text
Rule + Constraint + Ranking + ML
```

예시 입력 변수:

```text
Worker Availability
× Distance
× Experience
× Reliability
× Wage
× Store Requirement
```

#### 이유

- 점수 산출 기준을 설명할 수 있어야 함
- 필수 조건을 확실하게 차단해야 함
- 같은 입력에 일관된 결과가 필요함
- 편향과 차별 위험을 통제해야 함
- 추천 결과를 감사·검증할 수 있어야 함

## 13. LLM의 역할

LLM은 Match Engine 위에서 자연어 인터페이스와 설명·생성·조정 역할을 담당한다.

### Recruiting Copilot

입력:

> 토요일 오후 6시부터 사람 한 명 찾아줘.

조건 구조화:

```json
{
  "date": "Saturday",
  "start": "18:00",
  "headcount": 1
}
```

### Matching Explanation

> 이 근로자는 해당 매장과 1.2km 거리에 있고, 동일 업종에서 최근 3회의 근무 경험이 있으며 요청 시간대와 모두 일치합니다.

### 기타 역할

- Job Description 자동 생성
- Manager Copilot: 다음 주 인력 부족 시간 탐색
- Worker Copilot: 빈 시간에 가능한 일 탐색
- 후보 추천 이유 설명
- 정책·노무 정보 검색 보조

## 14. Local LLM·sLLM 전략

HR 데이터에는 다음과 같은 민감 정보가 포함될 수 있다.

- 이름
- 연락처
- 위치
- 근무 기록
- 급여
- 사업장 정보

모든 데이터를 외부 GPT·Claude API로 전달하기보다 **Hybrid AI Architecture**를 검토한다.

| Local AI Layer | Cloud LLM |
|---|---|
| 개인정보 처리 | 비민감 일반 텍스트 |
| 내부 검색 | 문장 생성 |
| 내부 RAG | UX Conversation |
| 민감정보 분석 | 외부 지식 기반 추론 |
| 비식별화·마스킹 | 비식별 데이터 후처리 |

### 원칙

1. PII와 민감 근무정보는 기본적으로 내부 처리한다.
2. 외부 전송 전 최소화·비식별화한다.
3. 접근 권한과 처리 로그를 남긴다.
4. 모델 선택은 비용보다 데이터 민감도와 업무 위험도를 우선한다.
5. 최종 채용·배제 결정은 설명 가능성과 사람의 검토를 보장한다.

## 22. 기존 제안서 문구 수정안

### 기존 문구

> 급구처럼 뛰어난 UX/UI를 코덱스로 구현할 수 있다면 Z세대 근로제공자를 유입하는 데 급구처럼 가능할 것이라고 생각합니다.

### 변경안

> 저희 팀은 이번 프로젝트를 단순히 급구와 유사한 채용 플랫폼을 구현하는 데 그치지 않고, 위솝이 이미 보유한 샵솔의 근태·급여·업무관리 영역과 신규 AI 채용 기능을 연결하는 방향으로 발전시켜 보고자 합니다.
>
> 특히 기존 구인 플랫폼이 `공고 → 지원 → 채용`을 중심으로 한다면, 위솝은 기존 사업장에서 발생하는 운영 데이터를 기반으로 `인력 수요 감지 → 시간 단위 매칭 → 실제 근무 → 근태·급여관리 → 재매칭`까지 연결할 수 있다는 차별점이 있다고 판단하고 있습니다.
>
> 이를 위해 저희 팀에서는 N잡 시장에 대한 CX/PX 도메인 경험과 함께 AI·LLM, Local LLM·sLLM, System Prompt Architecture, RAG, AI Agent, Workflow Automation 역량을 결합하여 실제 구현 가능한 AI Product Architecture와 MVP를 설계하고자 합니다.
>
> 특히 개인정보와 근무·급여 데이터의 민감도를 고려하여 모든 정보를 외부 LLM에 전달하는 구조가 아니라, Local AI와 Cloud LLM의 역할을 분리하는 Hybrid AI Architecture 역시 검토할 수 있습니다.
>
> 최종적으로는 단순히 또 하나의 구인구직 서비스를 만드는 것이 아니라, **위솝이 이미 보유한 Workforce Management 역량에 AI 기반 Workforce Marketplace를 결합하는 방향**을 기업과 함께 검증해보고 싶습니다.
