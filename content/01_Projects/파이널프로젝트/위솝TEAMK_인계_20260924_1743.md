## 1. 스토리 (발표·포트폴리오 공통)

1. **타겟 피벗**: 처음 기획은 "비는 시간에 일하고 싶은 N잡 근로자" 타겟, 근로자 UT 18명 → 위솝 회의 후 "진짜 병목은 사장님이 처음 보는 사람을 믿고 뽑을 근거가 없다는 것" 확인 → 타겟을 사장님으로 전환, 과제를 "어떤 기준으로 추천할 것인가"로 재정의
2. **두 신호 구분**: 결격 신호(무단결근·근무취소) vs 적합도 신호(신뢰성)
3. **UT 근거**: 사장님 4명 **전원** "취소·무단결근 1건이면 안 뽑는다"(추천서 최다 지원자도 예외 없음). 4회차에서 과거 근무자 실명 언급하며 동일 매장 경험자 선호 확인
4. **핵심 차별점 — 왜 샵솔이어야 하는가**: 다른 앱은 지원자가 "지금 어디 있는지"만 안다. 샵솔은 **몇 시에, 어느 매장에서 퇴근하는지** 안다(근무 스케줄 + 매장 위치)
   - ① **퇴근 후 N잡 연결**: 17시 샵솔 근무매장 퇴근 → 도보 12분 스시미찌 18시 스팟 (여유 48분)
   - ② **무단결근 사전 차단**: 샵솔 근무와 1분이라도 겹치면 지원 시 경고, 사장님 목록엔 "근무시간 겹침" 최하단
   - 처음의 N잡 타겟이 "가장 빨리 올 수 있는 공급자"로 돌아옴 → 피벗 이야기와 수미상관
5. **화면**: 점수 대신 순위 + 추천이유 한 줄
6. **킬러로직 (비중 5%)**: 핵심은 제재가 아니라 **공고에 적은 급여 지급 약속을 지키게 하는 것**. case1 매장 선결제 → 근무종료 1시간 후 [급여 받기] 버튼(시스템 확인) / case2 급여지급예정일 명시(2주 이내) → 약속일 23:59 근로자 확인. 늦게 준 것도 안 준 것과 같은 약속 미이행 → 반복되면 공고 등록 제한
7. **확장성**: 검증은 F&B부터. 업종 특화는 1순위 동심원뿐이라 다른 업종은 그 부분만 재정의하면 확장 가능 (근로자 UT 18명 중 3명 일감 종류 확대 요청 → 재택 게임테스터 N잡 확장 예시)
8. **회고**: 처음 가설이 틀려도 앞선 작업을 버리지 않고 새 구조 안에서 제자리를 찾아준다

## 4. 킬러로직 — 급여 약속 (9/24 17:43 확정)

**핵심**: 급여를 공고에 적은 시점에 주게 하는 것. 제재가 목적이 아님. 스팟워크는 당일 지급이 권장되고, **약속보다 늦게 주는 것 ≈ 안 주는 것** (2시간 늦어도 근로자에겐 체불과 거의 같은 효과).

- **입구**: 공고 등록 시 지급 방식 필수. case1 **매장 선결제(카드결제)**(기본) / case2 **급여지급예정일 일자 명시**(선결제가 어려울 때, 근무일로부터 **2주(14일) 이내**, 2주 안내는 공고 올리기 화면에만). 미선택 시 등록 불가, "추후 협의·월말 정산" 불가. 두 방식 모두 유지(선결제가 어려운 매장도 채용할 수 있어야 함)
- **확인 — case1은 시스템, case2는 근로자**
  - case1: 근무종료 1시간 후 근로자 화면 **[급여 받기] 버튼 활성** → 근로자가 눌러 받음. 시스템이 지급을 확인하므로 응답 알림 없음
  - case2: **지급예정일 당일 23:59** "급여를 받으셨나요?" **네😘 / 아니오😢** (근무 1건당 1회, 완료 기록 있는 근로자만, 무응답 집계 제외)
  - 아니오 → 그 시점에 **약속 미이행 1건 확정** + 사장님에게 "근로자가 급여를 아직 받지 못했다고 응답했어요" 알림
  - 나중에 받으면 근로자가 **받은 날짜 입력(보완)**. 날짜는 기록되지만 미이행은 지워지지 않고 **지연(약속일 대비 N일)**으로 남음. 화면 문구: "받은 날짜가 기록돼요. 약속일보다 늦게 받은 건 지연으로 남아요." 아직 못 받았으면 다음 날 다시 물음
- **출구 (최근 3개월, OR, case2만)**: ① 같은 근로자가 그 매장 2회차 이상 근무에서 **약속 미이행(미지급·지연) 4회 이상** ② 서로 다른 근로자 5명이 약속 미이행 → 신규 공고 등록 제한. 기준을 느슨하게 둔 이유: 제재가 아니라 약속을 지키게 하는 것이 목적
- **해제**: 최근 3개월 집계가 기준 아래로 내려가면 해제. **단, 아직 안 준 급여가 남아 있으면 해제 안 됨**(이체 증빙 + 근로자 받은 날짜 입력으로 해소). 늦게 준 건은 지연으로 남아 집계에 계속 들어감
- **폐기된 규칙**: "늦게 받으면 '받았어요'로 수정 → 집계 제외", case1 응답 알림, case2 "지급일 다음 날" 알림
- **근거**: 분위기 좋아 재방문하지만 2회차부터 급여가 늦는 패턴(544건 경험). 근무자가 직접 독촉하지 않고 앱 응답으로 목소리를 냄
- **발표 대비 한 줄**: case1 근무시간 변동 시 실제 퇴근 기록 기준 / 노쇼 시 선결제 환불
